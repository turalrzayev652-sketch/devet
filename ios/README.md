# ios

iOS app: Swift, SwiftUI, iOS 16+, `supabase-swift`. Bundle id `az.devet.app`, display name from `BRAND_NAME` (`Config/Base.xcconfig`).

Created in T41I (iOS counterpart of T41A). `Devet/Resources/Localizable.xcstrings` is generated by `/tools/i18n` — do not edit by hand.

## Build

```
# Xcode 16+ (project format 77, synchronized folders)
node tools/i18n/generate.mjs          # from the repo root, after changing spec/i18n/app.json
cd ios
xcodebuild test -project Devet.xcodeproj -scheme Devet -destination 'platform=iOS Simulator,name=iPhone 17'
```

Or open `Devet.xcodeproj` in Xcode and run the `Devet` scheme.

Supabase settings come from `Config/Secrets.xcconfig` (gitignored); copy `Config/Secrets.example.xcconfig`:

```
SUPABASE_URL = https:/$()/<project>.supabase.co    # xcconfig: "//" starts a comment
SUPABASE_ANON_KEY = <anon key>                      # anon only — never service_role
PUBLIC_BASE_URL = https:/$()/<guest domain>
```

Without them the app still builds and starts; repositories report `AuthFailure.notConfigured` (`SupabaseConfig.isConfigured`).

**Demo mode (Debug builds only):** launch with the argument `-DevetDemo YES` (Xcode: scheme → Run → Arguments, or
`xcrun simctl launch <device> az.devet.app -DevetDemo YES`) to start signed in with in-memory events
(`App/DemoBackend.swift`, inside `#if DEBUG`). Same sample data as Android's demo mode; not compiled into Release.

## Structure

- `Devet/Theme/` — design tokens from `/spec/design.md`: `Color.DS.*` (Asset Catalog `Resources/Colors.xcassets`, Any/Dark), `DevetType.*` + `.devetFont(_:)`, `Spacing`, `Radius`, `Sizes`, `Motion`. Same names and values as Android `ui/theme/`. `DesignTokensTests` fails if they drift from the spec.
- Colours are written by `swift scripts/generate-colors.swift ../spec/design.md Devet/Resources` (run from `ios/`) when design.md changes.
- `Devet/App/` — app entry, `AppDependencies` (environment object, the counterpart of Android's Koin module), `RootView` with `NavigationStack`.
- `Devet/Data/` — Supabase config and client; `Data/Auth/` — Supabase Auth (sign in/up, resend, reset, PKCE code exchange), errors mapped to `AuthFailure` (spec/api.md §0.2, same set as Android); `Data/Account/` — profile and `delete-account`.
- `Devet/Data/Events/` — screens [2] and [3]: `EventRepository`, `EventRules` (validation, Baku time, 7-day archive, changed columns), `MapsLink` (`spec/test-vectors/maps.json`), local "Arxivlə" (`ArchiveStore`). `UI/Events/` — list, 6-step wizard, edit page. The map field uses the system `PasteButton` (no paste prompt; its label comes from iOS).
- `Devet/Data/Guests/` — screen [7]: `Phones` (`phones.json`), `ExcelRules` (`excel.json`), `XlsxReader` (ZIPFoundation + XMLParser), `DisplayNames` (`invite.json` forms for the preview), `GuestRepository` (one batch insert; limit refusal → `.limitExceeded`). `UI/Guests/` — add guests (manual · contacts · Excel), event home until the guest list (T46). Contacts use `CNContactPickerViewController` (several contacts, no permission; presented from UIKit — inside a SwiftUI sheet it stays blank); a contact with several mobile numbers gets a choice dialog (§15.7).
- The "Copy shared spec files" build phase puts `spec/test-vectors/excel.json`, `phones.json`, `spec/i18n/invite.json` and the sample `guests-sample.xlsx` (same file as Android's asset) into the app bundle on every build — never edit copies.
- `Devet/UI/Auth/` — screens of [1]; `UI/Settings/` — [12b]; `UI/Events/` — [2] shell until T43. `App/AppModel` decides the root screen from the session (`rootFor`, same rule as Android).
- E-mail links: `az.devet.app://auth/callback` and `az.devet.app://auth/reset-password` (URL scheme in `Config/Info.plist`, handled by `.onOpenURL`). Supabase → Authentication → URL Configuration → Redirect URLs must contain `az.devet.app://auth/**`.
- App language: chosen in iOS Settings → Devet → Language (owner's decision 2026-10-31); the Settings screen opens that page and keeps `profiles.ui_lang` equal to the UI language.
- Languages: az (development language), ru, en, tr. The app follows the system language; the per-app language (Settings → Devet → Language) works because the bundle ships all four localizations.
- Tests: `AuthRulesTests` and `AuthViewModelsTests` mirror the Android tests case by case; `SupabaseAuthRepositoryTests` runs the real supabase-swift client against a stubbed `URLProtocol` (GoTrue 2024-01-01 error format).
- Fonts: `Resources/Fonts/` — the same variable TTFs as Android, registered in `Config/Info.plist` (`UIAppFonts`); the weight is set on the `wght` axis.
- The project file is hand-written (no XcodeGen/Tuist): with synchronized folders new files under `Devet/` and `DevetTests/` are picked up automatically, so the project file rarely changes and one less tool is needed.

## Dependencies and why

| Library | Why |
|---|---|
| supabase-swift 2.55.6 (exact, SPM; product `Supabase`) | backend client required by CLAUDE.md; pulls in its own Auth/PostgREST/Storage/Functions modules and swift-crypto, swift-http-types, swift-clocks, swift-concurrency-extras, xctest-dynamic-overlay (versions locked in `Package.resolved`) |
| ZIPFoundation 0.9.20 (exact, SPM) | reading `.xlsx` (a zip archive) for the guest import — iOS has no public zip API (owner's decision 2026-10-31) |
| Inter, Noto Serif Display (OFL, `licenses/`) | fonts from spec/design.md; bundled so Azerbaijani letters (ə, ğ, ı, ö, ş, ü, ç) render the same on every device |
